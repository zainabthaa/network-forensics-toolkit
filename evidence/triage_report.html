What the flow data shows

  1. 22/22 TCP flows last ~5.0s from SYN to FIN regardless of how much data they carry: connection lifetime is set by the HTTP keep-alive idle timeout (about 5s), not by user activity. Every connection is closed 5.00–5.02s after its last data packet; in 6 flows both FINs cross on the wire (simultaneous close), so client and server time out together.
  2. Traffic is strongly asymmetric: 93.1% of bytes flow server-to-client (page and image downloads), 6.9% client-to-server.
  3. The two largest flows (#7, #6) carry 73.3% of all TCP bytes: GET /docs/graphics/docker/detail.png; GET /instructions.php, GET /docs/graphics/docker/overview.png.
  4. The browser opened up to 2 parallel TCP connections (peak at ~48s) to fetch embedded resources concurrently.
  5. Connections are reused for up to 2 requests (HTTP/1.1 persistent connections).
  6. Every TCP flow has a complete three-way handshake and an orderly FIN teardown; no resets, scans or half-open connections were observed.
  7. 100% of TCP flows are cleartext HTTP on port 80; no flow is encrypted.
  8. The server's packets arrive with TTL 63 while the client's leave with 64: both look like Linux (initial TTL 64), but the server sits 1 routed hop away despite sharing the subnet, consistent with DVWA running in a container behind the VM's bridge.
  9. Every MAC address is locally administered (randomised/virtual), as expected for VM network adapters; no vendor OUI is present.
  10. A third device (3e:06:30:63:f6:65) only sends IPv6 router advertisements to ff02::1: the hypervisor's virtual-network gateway, not a participant in the session.
  11. 39 frames are larger than the 1,514-byte Ethernet MTU (up to 33,090 B): an artefact of segmentation offload (GRO/LRO) on the capturing NIC, not jumbo frames on the wire. Byte counts are right; per-frame counts are understated.
  12. TCP health is clean: handshake RTT 0.693–4.158 ms (median 1.777 ms), 0 retransmissions, 0 zero-window events. The slowest server response is POST /login.php at 71.913 ms.
  13. Separated by idle gaps of ≥10s, the session forms 7 activity bursts; the median time between new connections is 11.224s, a human browsing pace rather than automated traffic.
  14. Only 2 IPv4 hosts exchange application traffic; the remaining frames are link-local ARP / IPv6 neighbour-discovery noise.
